## 一、项目定位

一个**统一服务器管理与开发平台**：把服务器、网站、域名、Docker 应用收进一个 Web 界面，
并对外提供 **MCP Server**，让 AI 开发工具（Trae / Cursor / Claude 等）能直接调用这些能力。

设计原则：**宝塔面板退居底层**——只负责运行本系统与提供基础 API，
日常操作全部在工作台里完成，不再来回切换面板。

| 项 | 值 |
| --- | --- |
| 访问地址 | https://aige-saas-panel.miaocaieyc.com.cn |
| MCP 地址 | https://aige-saas-mcp.miaocaieyc.com.cn（SSE） |
| 部署路径 | `/root/aige-saas-workbench/`（服务器 `120.53.102.56`） |
| 二级域名约定 | 本项目一律 `aige-saas-<角色>`（2026-10-07 确立） |

## 二、技术栈（锁定）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router + Axios + ECharts | Element Plus **按需引入**，图标只注册用到的 |
| 后端 | Node.js + Express | 分层：routes / services / db / middleware / mcp |
| 数据库 | SQLite（better-sqlite3） | 本地开发无工具链时自动回退 Node 内置 `node:sqlite` |
| MCP | `@modelcontextprotocol/sdk`（官方） | SSE + stdio 双传输 |
| 容器化 | Docker + docker-compose | 前端 Nginx 托管 + 反代 /api |
| 反向代理 | 宝塔 Nginx | 指向本机 8083（前端） |

## 四、MCP 连接配置（2026-10-07 重做）

**修复前的问题（真实存在，会让配置完全不可用）：**

```json
{
  "url": "http://<域名>:3001/sse",              // ❌ http + 内网端口，外网连不上
  "headers": { "Authorization": "Bearer <尚未生成令牌>" }  // ❌ 占位符，还要手动填
}
```

**现在的要求（三条硬标准）：**

1. 地址必须来自 `PUBLIC_MCP_URL`，是**外网真正可达的 https 域名**；
2. 令牌**绝不下发占位符**——没有就当场生成一个；
3. 结构用 `mcpServers` 通用格式，Trae / Cursor / Claude 都能直接粘。

产出（粘贴即用，无需任何手填）：

```json
{
  "mcpServers": {
    "aige-workbench": {
      "url": "https://aige-saas-mcp.miaocaieyc.com.cn/sse",
      "headers": { "Authorization": "Bearer <真实令牌>" }
    }
  }
}
```

相关配置项：

| 环境变量 | 用途 |
| --- | --- |
| `PUBLIC_PANEL_URL` | 工作台对外地址 |
| `PUBLIC_MCP_URL` | MCP 服务对外地址 |
| `MCP_AUTH_TOKEN` | 初始令牌（没有时系统会自动生成并存库） |
