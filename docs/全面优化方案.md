## 一之二、2026-10-08 本轮完成情况（对照上表）

### ① 数据正确性：CPU / 负载 / 运行时长全是错的（已修）

实测对照（这才是真正的"隐性 bug"——错得很安静）：

| 指标 | 修复前显示 | 系统真实值 | 根因 |
| --- | --- | --- | --- |
| CPU 使用率 | 97.5% / 100% | ≈58% | 宝塔 `cpuRealUsed` 本身不准 |
| 系统负载 | `0 / 0 / 0` | 1.43 / 1.58 / 1.47 | 宝塔返回的 `load` 是**空格分隔字符串**，代码按对象取 → 永远 undefined |
| 运行时长 | `null` | 18 天 | 宝塔 `setup_time` 取不到 |
| 资源曲线 | 空（1 个点） | — | 样本只存在前端内存里，刷新即丢 |

**做法**：新增 `services/metrics.js`（直读 `/proc/stat` 两次采样算差值、`/proc/loadavg`、
`/proc/uptime`、`/proc/meminfo` 用 `MemAvailable`、`fs.statfsSync` 取磁盘）+
`services/metricsStore.js`（每 2 分钟落一条、保留 30 天、按时间桶聚合）。
宝塔只保留它擅长的系统版本与分区明细；宝塔挂了这套照样出数。

> 💡 **一个大坑顺带验证掉了**：容器里读 `/proc` 拿到的是**宿主机**的值
> （loadavg / uptime / cpu 都不是 namespaced 的），已实测比对一致。

### ② 卡顿根因：303KB 的 JS 被钉在首屏（已修）

`vite.config.js` 里给 element-plus 指定了固定 chunk 名，Rollup 就把**全站用到的所有**
组件（日期选择器、上传、树、走马灯…大多只属于设置页/网站页）塞进同一个文件；
而入口又静态引用了它 → `index.html` 里出现 `modulepreload` →
**登录页/仪表盘必须先下 302KB gzip 的 JS**。

| | 修前 | 修后 |
| --- | --- | --- |
| 首屏（3 个文件合计） | 1455KB raw / **427KB gzip** | 630KB raw / **154KB gzip** |

已在 CI 里加了「首屏预算看门狗」（>220KB 直接失败），防止后面又被拽回去。

### ③ 主题色做成可切换预设（默认取自 logo）

主人说「别光使用绿色的颜色，试用好几种颜色」→ 不是再挑一个自定义色，

入口：**系统设置 → 外观**。机制与新增预设的方法见 `docs/ui设计规范.md` §2.1。

### ⑥ B2 变更历史 + 一键回滚（已完成，端到端验收通过）

站点详情新增「**配置历史**」页签：列出该站点自己的全部配置备份 → 看任意一份与「当前线上」的
行级差异 → 一键回滚。三个 REST 接口：

```
GET  /api/websites/:name/snapshots          列出备份 + 当前线上配置
GET  /api/websites/:name/snapshots/diff     两份配置的行级差异（LCS + 4 行上下文折叠）
POST /api/websites/:name/snapshots/restore  回滚（服务端强制要求 confirm:true）
```

**回滚语义（最容易搞反的一点，已在代码与文档里写清）**：
每份备份 = 「某次改动发生前」的原配置。所以回滚到**最新**那份备份，得到的是
**上一次变更之后**的状态，而不是最初的状态。要回到最初，得回滚到**最早**那份。

**安全性（这段逻辑单独抽成了零依赖模块 `utils/safePath.js`）**：
备份目录 `/www/server/panel/vhost/nginx` 里躺着**全服务器所有站点**的配置
（koyca / rpoiyc / tito-* 都不属于本项目），一个 `../` 就能读到别人的东西 —— 这是本项目
最不能出的事。所以站点名与备份文件名都要过白名单，且校验逻辑被抽成
**零依赖模块 + 可执行自检脚本**（`backend/scripts/selfcheck-path-guards.js`，
23 个越权样本全部拦住），由 CI 每次真跑一遍。

**实测（E2E，全程只用本项目自己的 aige-saas-* 资源）**：
建临时站点 → 制造两次配置变更 → 列快照（2 份）→ 差异正确（+1/−1）→
缺 confirm 被拒 400 / 非法站点名被拒 400 / 备份名穿越被拒 400 →
两步回滚后配置 **md5 逐字节回到最初版本** → 探活正常 → 清理临时站点。

**顺手修掉两个真 bug**：
1. `baota.listDir()` 读 `res.FILE`，实际字段是 **`FILES`** → 文件列表**永远是空的**。
   此前唯一调用方只关心子目录所以没暴露，做配置快照时才撞出来。
2. 请求体 JSON 语法错误被当 500 返回（应 400）—— 调用方会去后端日志里找一个不存在的 bug。

### ⑦ 告警第三通道：企业微信群机器人（已完成）

飞书与企微是**两种协议，地址不能混填**（这是最容易踩的坑）：
飞书 `{msg_type, content}` 判 `code`；企微 `{msgtype, markdown}` 判 `errcode`。
企微推 markdown 卡片、按严重度标色，并把常见 errcode 翻译成人话
（93000 = webhook key 复制少了）。三个通道**并行**推送，互不影响。

## 三、P1 高价值（建议接下来按序做）

### B1 · 告警通道 ✅ 已完成（2026-10-07）

**为什么**：所有结论以前只躺在页面里，没人打开就不知道。这是"别人都有、我们没有"的最大缺口。
**做法**（三档，站内必开，外部可选）：
1. 站内告警中心 —— 顶栏铃铛 + 未读红点 + 抽屉列表，问题消失后自动关闭
2. 通用 Webhook —— 告警产生时 POST 一段 JSON（level / title / detail / 时间）
3. 飞书机器人 —— 走自定义机器人协议，国内可达、零成本

**触发源**：巡检 critical/warning、部署失败、自愈失败。
**防刷屏（这是告警系统能不能用的关键）**：
- 按 `fingerprint` 去重 —— 同一问题未解决时只累加次数，不新增行
- 30 分钟静默窗口 —— 同一告警只外推一次
- `ok` 的检查项会**自动关闭**对应告警
- 已解决的告警每天清理，只留最近 200 条

**实现要点**：
- `services/notify.js` 用 `raiseDetached()` 产生告警 —— 外发 webhook 最长等 10 秒超时，
  在巡检里 await 会把接口拖慢（监控不能反过来拖垮主流程）
- 顶栏只轮询 `/api/alerts/summary`（一个 COUNT），列表打开抽屉时才拉
- Webhook / 飞书地址按敏感项 AES 加密存储，界面只回显掩码

**验收**：告警表建好；巡检产出告警；**重复巡检去重生效（条数不变、次数 1→2）**；
已读 / 标记解决可用；未配通道时测试接口给出明确提示。

**下一步（B1 的后续，未做）**：把「配置项变更」也纳入告警源；告警按天汇总发一份日报。

### B2 · 变更历史 + 一键回滚

**为什么**：`save_nginx_config` / `setReverseProxy` 已经会把原配置备份成 `.conf.bak.<时间戳>`，
但**没有任何入口能回滚** —— 等于买了保险却没留理赔电话。
**做法**：新增「配置快照」列表（按站点聚合 .bak 文件），每条可「预览差异 / 一键回滚」；
回滚本身也先备份当前版本（可再回滚回去）。
**影响面**：后端读目录 + 差异对比；新增站点详情里的一个页签。
**风险**：中 —— 回滚会改线上配置，但**每次回滚前都先备份**，且必须二次确认。
**验收**：造一个坏配置 → 回滚 → 站点恢复访问。

### B3 · 资源趋势落库（7 / 30 天）

**为什么**：现在只有"最近 10 分钟"，看不出磁盘是不是在稳步上涨、内存有没有缓慢泄漏。
**做法**：后端每 5 分钟采样一次（CPU / 内存 / 磁盘 / 容器数）写入 SQLite，
自动只保留 30 天（老数据定期删，**不会把磁盘写满** —— 预估 30 天约 1–2MB）。
仪表盘图表加「1 小时 / 24 小时 / 7 天 / 30 天」切换。
**影响面**：新增采样表 + 定时器 + 图表改造。
**风险**：低（数据量极小）；注意采样任务本身要轻。

### B4 · 代码仓库页（GitHub 集成）✅（2026-10-08 已完成，只读版）

1. **配额是这个功能最大的敌人。** 匿名只有 **60 次/小时，按服务器出口 IP 算**（全服务器共用）。
   一个页面要 5 个请求 → 刷十几次就打满。所以做了两层保护：60 秒缓存 + 把

### B5 · 多角色权限 ✅（2026-10-08 已完成）

**为什么**：`users.role` 字段一直是摆设 —— 所有接口只挂了 `requireAuth`，
**任何登录用户都是全权**（`requireAdmin` 定义了但从未被使用过一次）。

**做法**：三个角色 + 一张集中的权限规则表。

| 角色 | 能做什么 |
| --- | --- |
| `viewer` 只读 | 看全部运维数据；**任何写操作被服务端拒绝** |
| `operator` 运维 | 网站 / DNS / 容器 / 部署 / 巡检修复；**改不了系统设置、管不了账号** |
| `admin` 管理员 | 全权（含系统设置、MCP 令牌、用户管理） |

四个关键设计（这块最怕"以为锁了、其实没锁"）：

1. **规则集中在 `middleware/permissions.js`**，按「模块路径 + 方法」判定，
   挂在 `routes/index.js` 的每一行挂载上。⚠️ 不在各路由文件里手写角色判断 ——
   那样一定会有漏的，而漏掉的那一个接口就是「所有人都能全权操作」。
2. **CI 兜底**：`scripts/selfcheck-permissions.js` 遍历**真实路由栈**，断言
   「每个业务模块都挂了 `requirePermission`」且「挂载的模块与规则表里的模块完全一致」。
   漏挂一个模块 / 新模块忘了归类，直接红。（做过反向验证：故意摘掉一个模块的中间件，
   它会精确点名 `××（缺 requirePermission）`。）
3. **角色每次从数据库现查，不信 JWT 里那份**。令牌是自包含的，签发时是什么角色就一直
   是那个角色 —— 如果信它，把某人降级后他手上的旧令牌仍然是管理员，要等令牌过期才生效。
   `signToken` 里索性不再放 role，从源头断掉误用的可能。
4. **系统设置整块（含读）只给管理员**：里面有宝塔密钥、Cloudflare Token、MCP 令牌、
   机器人 Webhook，「能看到」约等于「能拿到半台服务器」。「只看不改」对这块没有意义。

**配套**：新增用户管理（`routes/users.js` + 设置页「用户与角色」段）——
建号 / 改角色 / 重置密码 / 删除，含两条防自锁约束（不能降级或删除自己、
不能干掉最后一个管理员）。

**验收**（`.deploy/verify-b5.js`，端到端全部通过）：
只读身份下 10 个写接口全部 403、3 个读接口正常；系统设置与用户管理对只读、
运维都返回 403；只读也能改自己的密码；**改角色后旧令牌立即生效/失效（不重登）**；
不能给自己降级、不能删自己；测试账号跑完即删。

前端：侧边栏按角色过滤（只读看不到「系统设置」）、路由守卫拦 `adminOnly` 页面、
各列表页隐藏写按钮并给出「你当前是只读身份」的说明条（`components/ReadOnlyNotice.vue`）。

### B6 · 审计 diff ✅（2026-10-08 已完成）

**为什么**：日志原来只记「改了设置」，不记「从什么改成什么」。出问题时要对账，
只能看到一条「保存配置」，等于没有信息。

**做法**：`operation_logs` 加 `before_value` / `after_value` 两列（存 JSON，按字段），
仪表盘「最近操作」在动作下方直接渲染成 `字段  旧值 → 新值`。

**已接入的写入方**：

| 写入方 | 记录内容 |
| --- | --- |
| 系统设置（`PUT /api/settings`） | 每个改动字段的旧值 → 新值 |
| DNS 更新（网页） | type / name / content / proxied 的对照 |
| DNS 更新（MCP 的 `update_dns_record`） | 同上（走 `audit` 约定，见下） |

三条实现上的硬约束：

1. **⛔ 敏感值绝不能落库**。防线放在**源头**而不是调用方：
   `settings.applyPatch()` 在返回改动明细时就把敏感项替换成 `已设置 / 未设置`，
   调用方**根本拿不到明文**，所以不可能写进去。
   （验收脚本专门做了一条硬断言：读数据库**原始行**全文搜那个假密钥，
   出现在任何一列就算失败。）
2. **没有实际改动就不写日志**。否则"点一次保存但什么都没改"也会留一条空记录，
   真正的记录反而被埋掉。顺带把「值没变不算改动」判断做准（原来是只看有没有传值）。
3. **新列必须同时改两处**：`schema.sql`（新库）与 `db/index.js` 的 `migrate()`（已有库）。
   只改前者的话，已在跑的那台库永远没这两列，而且**不报错**。

**MCP 侧约定**：工具可以多返回一个 `audit: { before, after }`，由 `callTool` 写进操作日志后
**剥掉不外传** —— 工具对 AI 的返回结构始终是 `{ success, data, message }`，
免得客户端那边多出一个没人认识的字段。

**验收**（`.deploy/verify-b6.js`，端到端全部通过）：
非敏感项 before/after 与真实旧值新值逐字一致；重复保存不产生新日志（161 → 161）；
敏感项只记「未设置 → 已设置」；**全表原文扫描确认明文零泄漏**；
MCP 路径同样留痕且 `audit` 字段未泄漏到返回值；测试配置与临时 DNS 记录均已还原/删除。

### D1 · 登录二次验证（TOTP）✅（2026-10-08 已完成）

**为什么**：面板直接暴露公网，此前**密码是唯一防线**。密码一旦泄露（复用、被撞库、
在别处被钓），服务器就是别人的了。

**做法**：标准 TOTP（RFC 6238），Google Authenticator / 微软验证器 / 1Password /
Authy 都能扫。绑定入口在「系统设置 → 登录二次验证」。

四个关键设计（这块最怕「把自己关在门外」）：

1. **⛔ 先给恢复码，再让用户输码启用**。顺序反过来（先启用、再显示恢复码）的话，
   用户手机一丢就彻底进不来，只能上服务器改数据库 —— 这是这类功能最典型的自锁。
   实现上 `setup` 就把密钥**和 10 个恢复码**一起给出，`enable` 只是确认。
2. **密码只换临时票据，不发登录令牌**。密码对但启用了二次验证时，后端只返回
   `{ needTotp, ticket }`，ticket 是 5 分钟有效的 JWT（`scope='totp'`），
   **它不能当登录令牌用**：`requireAuth` 只认 `scope='session'`。
   否则"输完密码"这一步就已经有完整权限，二次验证等于白做。
3. **恢复码一次性 + 只存 sha256**。用掉就从列表里删；入库前归一化
   （大写、去掉连字符/空格），所以用户抄成 `a3f9 k2mp` 也能用。
4. **关闭要密码 + 动态码**。只凭一个登录会话就能关掉二次验证的话，
   会话被盗之后这道防线形同虚设。

**实现取舍**：算法自己写（`utils/totp.js`，约 150 行），**不引 otplib** ——
这是安全功能，少一个供应链面；而且零依赖才能让
`scripts/selfcheck-totp.js` 拿 **RFC 6238 附录 B 的六个官方时间点**逐字节比对
（验证码算错的表现是「一直提示验证码不对」，人只会怀疑手机时间不准，很难查）。

**验收**（`.deploy/verify-d1.js`，端到端全部通过，全程只在一个临时账号上操作）：
绑定前登录不受影响；错码不能启用；启用后密码只给票据；**拿票据当令牌打接口 → 401**；
验证码换到真令牌；恢复码能登录且**用第二次被拒**（数量 10 → 9）；
格式容错生效；密码错误不能关闭；关闭后登录恢复成一步；测试账号跑完即删，
管理员状态未被改动。

前端：登录页多一步验证码（含「验证器不在身边？用恢复码」切换）；
设置页新增「登录二次验证」段（二维码 + 密钥 + 恢复码 + 状态）。
二维码用 `qrcode` 库**动态加载**（单独 chunk，只在打开绑定弹窗时下载，不进首屏预算）。

### D2 · MCP 只读令牌 ✅（2026-10-08 已完成）

**为什么**：MCP 原来只有一把「万能钥匙」，给出去就是全权 —— 一个只会「看看服务器状态」的
AI 助手，理论上也能 `delete_website`。

**做法**：令牌分两级，**级别由「用哪把令牌」决定，与客户端自称什么无关**。

| 级别 | 工具数 | 生成方式 |
| --- | --- | --- |
| 全权 `full` | 30 | 默认就有；可「重新生成」 |
| 只读 `readonly` | 17 | 系统设置 → MCP → 「生成只读令牌」（可吊销） |

**拦在两道门上**（这一条是安全的关键）：

1. `ListTools` 只回只读工具 —— 这是**建议**，让 AI 一开始就知道边界，不会白试；
2. `CallTool` 命中写工具直接拒绝 —— 这是**强制**。AI 完全可以无视清单硬调，
   只做第 1 条等于没做。

> ⚠️ 还有一个非直觉但必须做的点：**sessionId 必须与令牌级别绑定**。
> SSE 模式下 `/sse`（建连）与 `/messages`（发消息）是两个请求，若 `/messages` 只验
> 「令牌有效」而不比对级别，那么拿只读令牌 + 猜到的 sessionId 就能指挥一个全权 session
> —— sessionId 是可猜、可泄漏的，**不能当凭据用**。现已返回 `403 SCOPE_MISMATCH`。

**归类白名单**：`tools.js` 的 `READONLY_TOOLS`（未列出的默认不给只读令牌用 ——
新增工具忘归类时，错在保守这一边）。`WRITE_TOOLS` 与它必须**恰好铺满全部工具且互不重叠**，
由 `backend/scripts/selfcheck-mcp-scope.js` 在 CI 里强制（本地 `npm run check:scope`）。

`run_health_checks` 归只读是**有意的取舍**：它写告警、可能外发，但不碰服务器本身，
且正是只读 AI 最该干的事；告警有指纹去重 + 30 分钟静默窗口，反复触发也刷不了屏。

**验收**（`.deploy/verify-d2.js`，端到端 11 组断言全部通过）：
只读连接可见 17 个工具、`list_websites` 可用；`delete_website` / `call_bt_api` 均被拒
且理由是「只读令牌无权调用」；拿全权令牌打只读 session → 403；全权连接仍是 30 个工具
且同一调用走业务逻辑（未被误伤）；吊销后原令牌立刻 401、全权令牌不受影响。

## 四、P2 体验与视觉（E1 / E2）

> 原则：**每个特效都要有降级路径，手机端与低配设备不掉帧**。
> 明确不引 Three.js 全景 3D —— 光运行时 3.2MB gzip，这台 2 核机器和手机端都要掉帧，
> 那是"为了炫牺牲流畅"，与本方案 0.3 条冲突。

### E1 · 便利性（低风险，高感知）

| 项 | 说明 |

### E2 · 动效与视觉特效（务实路线）

**动效层（先把地基打好）**

**3D / 高级特效（全部零依赖、可降级）**
| 位置 | 效果 | 代价 | 降级 |

## 六、明确不做（及理由）

| 不做 | 理由 |
| --- | --- |
| **定时备份 / 自动备份** | 你明确说不要；服务器 40G 已用 59%，备份会吃掉最后空间 |
| 多服务器纳管 | 需求还没出现，过早抽象会让所有接口都多一层"选服务器" |
| 接管 WAF / 防火墙 | 风险高（改错直接把公网访问切断），宝塔自带够用 |
| Three.js 全景 3D、大颗粒粒子 | 违背"流畅度"要求，2 核服务器与手机端都会掉帧 |
| Grafana / Sentry / ELK 自托管 | 内存与存储都撑不住，且与本系统职责重叠 |
| 引入付费组件库 | 你的红线：只用免费开源（MIT） |
