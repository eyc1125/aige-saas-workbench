# 艾哥 SaaS 工作台 · 全面优化方案

> 目标：**别人有的我们都有，别人没有的我们做得更好**；同时保证这台 2 核 / 2GB 服务器
> 与手机端都跑得舒服（不为了炫技牺牲流畅度）。
>
> 本方案由 AI 拟定，逐项给出「为什么值得 / 怎么做 / 影响面 / 风险 / 怎么验收」，
> 便于逐条拍板。执行顺序默认按编号，可随时插队或砍掉。

最后更新：2026-10-07 · 版本 v1

## 二、A1 · 主色换成"真正的绿色"（本轮已完成）

**为什么**：v3 的 `#0b6b47` 偏青、明度太低，观感像"深墨绿"而不是绿。
**做法**：主色改 **森林绿 `#15803d`**（hue ≈142°）。

三条硬约束同时满足，才敢定这个值：

| 约束 | 结果 |
| --- | --- |
| 白字压底 ≥4.5:1（按钮文字） | `#15803d` = **5.0:1** ✅ |
| 大面积铺底不刺眼 | 荧光绿 `#22c55e` 只有 3.3:1，压白字不合格，弃用 |
| 与警告/危险色并排不抢戏 | 琥珀 `#a9600a`、砖红 `#c62f2f` 与它区分明确 |

配套调整：
- 渐变两端都过对比度校验（`#15803d → #106a32`，5.0:1 / 6.7:1），不用"只亮一端"的假渐变
- 品牌标记单独用更艳的 `#1a9c4d`（图形标按 3:1 判定，可以更绿）
- 中性色阶、阴影、深色主题（`#3ddc84`）全部跟绿
- **`--success` 与主色同值（刻意）**：绿色主题下"健康"就是品牌色；需要区分两个绿块时改用法
  （已把仪表盘图例里的"镜像数"从绿改成 info 蓝）

## 三、P1 高价值（建议接下来按序做）

### B1 · 告警通道 ✅ 已完成（2026-10-07）

**为什么**：所有结论以前只躺在页面里，没人打开就不知道。这是"别人都有、我们没有"的最大缺口。
**做法**（三档，站内必开，外部可选）：
1. 站内告警中心 —— 顶栏铃铛 + 未读红点 + 抽屉列表，问题消失后自动关闭
2. 通用 Webhook —— 告警产生时 POST 一段 JSON（level / title / detail / 时间）
3. 飞书机器人 —— 走自定义机器人协议，国内可达、零成本

**触发源**：巡检 critical/warning、部署失败、自愈失败。
**防刷屏（这是告警系统能不能用的关键）**：
- 按 `fingerprint` 去重 —— 同一问题未解决时只累加次数，不新增行
- 30 分钟静默窗口 —— 同一告警只外推一次
- `ok` 的检查项会**自动关闭**对应告警
- 已解决的告警每天清理，只留最近 200 条

**实现要点**：
- `services/notify.js` 用 `raiseDetached()` 产生告警 —— 外发 webhook 最长等 10 秒超时，
  在巡检里 await 会把接口拖慢（监控不能反过来拖垮主流程）
- 顶栏只轮询 `/api/alerts/summary`（一个 COUNT），列表打开抽屉时才拉
- Webhook / 飞书地址按敏感项 AES 加密存储，界面只回显掩码

**验收**：告警表建好；巡检产出告警；**重复巡检去重生效（条数不变、次数 1→2）**；
已读 / 标记解决可用；未配通道时测试接口给出明确提示。

**下一步（B1 的后续，未做）**：把「配置项变更」也纳入告警源；告警按天汇总发一份日报。

### B2 · 变更历史 + 一键回滚

**为什么**：`save_nginx_config` / `setReverseProxy` 已经会把原配置备份成 `.conf.bak.<时间戳>`，
但**没有任何入口能回滚** —— 等于买了保险却没留理赔电话。
**做法**：新增「配置快照」列表（按站点聚合 .bak 文件），每条可「预览差异 / 一键回滚」；
回滚本身也先备份当前版本（可再回滚回去）。
**影响面**：后端读目录 + 差异对比；新增站点详情里的一个页签。
**风险**：中 —— 回滚会改线上配置，但**每次回滚前都先备份**，且必须二次确认。
**验收**：造一个坏配置 → 回滚 → 站点恢复访问。

### B3 · 资源趋势落库（7 / 30 天）

**为什么**：现在只有"最近 10 分钟"，看不出磁盘是不是在稳步上涨、内存有没有缓慢泄漏。
**做法**：后端每 5 分钟采样一次（CPU / 内存 / 磁盘 / 容器数）写入 SQLite，
自动只保留 30 天（老数据定期删，**不会把磁盘写满** —— 预估 30 天约 1–2MB）。
仪表盘图表加「1 小时 / 24 小时 / 7 天 / 30 天」切换。
**影响面**：新增采样表 + 定时器 + 图表改造。
**风险**：低（数据量极小）；注意采样任务本身要轻。
**验收**：跑满 1 小时后能看到真实曲线；确认行数与体积符合预估。

### B4 · 代码仓库页（GitHub 集成）

**为什么**：你点名要 GitHub；且"改了什么代码"和"线上跑了什么"应该在一个后台里看得见。
**做法**：利用**已授权的 GitHub 连接**（不用你去配 MCP），新增「代码仓库」页：
- 仓库列表 / 最近提交 / 分支
- GitHub Actions 运行状态（成功/失败，点进去看日志）
- 打开 Issues、创建 Issue（把巡检问题一键转成 Issue，这是很实用的联动）
- 一键创建仓库 / 发布 Release

**影响面**：新增 1 个页面 + 路由 + 导航。
**风险**：中 —— 需要你授权仓库范围；只读+受限写，不做强删。
**验收**：能看到本项目的提交与 CI 状态；能从巡检页把一条告警转成 Issue。

### B5 · 多角色权限

**为什么**：`users.role` 字段与 `viewer` 角色是预留的，现在没真正用起来。
**做法**：`admin`（全权）/ `operator`（可操作，不可改配置与账号）/ `viewer`（只读）；
后端每个写接口加角色校验，前端按角色隐藏按钮。
**影响面**：`middleware/auth.js` + 各写接口 + 用户管理页。
**风险**：中 —— 改鉴权容易改漏，必须逐接口过一遍并写用例。
**验收**：用 viewer 账号登录，确认所有写操作都被拒（而不是只隐藏按钮）。

### B6 · 审计 diff

**为什么**：现在的日志记录"改了设置"，但没记录"从什么改成什么"，出问题对不上账。
**做法**：日志表加 `before` / `after` 两个字段；配置类操作统一记录差异（敏感值只记"已修改"）。
**风险**：低；注意**绝不能把密钥明文写进日志**。
**验收**：改一次配置，日志里能看到字段级的 before/after。

### C1 · 自愈检查项扩展（候选清单）

已建成 6 项（证书到期 / HTTPS 覆盖 / CF SSL 模式 / 容器状态 / 磁盘水位 / 口令自查）。
下面这些是"重复出现且有确定修法"的下一批，按性价比排序：

| 候选检查项 | 触发条件 | 修法 | 自动 |
| --- | --- | --- | --- |
| 容器重启循环 | 同一容器 1 小时内重启 > 3 次 | 停止重试 + 告警（防风暴） | ✅ |
| 证书链完整性 | 源站证书缺中间证书（部分客户端报错） | 重新签发（LE 带链） | ✅ |
| CF 缓存漂移 | 静态资源被缓存成 HTML / 改版后仍旧 | 清缓存 | ✅ |
| 内存水位 | 可用内存 < 10% 持续 5 分钟 | 清 dangling 镜像 + 报告内存 Top 容器 | ✅ |
| DNS 漂移 | 本项目站点域名在 CF 无对应 A 记录 | 补记录（需确认） | ✖ |
| 站点配置错位 | 有证书但 Nginx 没有 443 段 | 重写配置（需确认） | ✖ |
| 日志膨胀 | 单站点 access log > 500MB | 轮转（需确认） | ✖ |

**这批的价值**：每一条都是真踩过的坑，做进去就是"下次不用再手动救"。

### C2 · 事件驱动自愈

**为什么**：定时巡检最快也要等一个周期；容器崩了应该**立刻**知道并处理。
**做法**：监听 Docker events（`/events` 流），容器 `die` 事件 → 立刻针对该容器跑一次
`container_down` 检查并按策略处理；同样受熔断与白名单约束。
**风险**：中 —— 事件流要保持长连接，断线要能自动重连；必须防"崩溃-重启-崩溃"循环。
**验收**：手动 kill 一个测试容器，确认 10 秒内被处理且日志有记录。

### D1 · 登录二次验证（TOTP）

**为什么**：面板直接暴露公网，`elyac` 目前还是默认口令。密码泄露 = 服务器沦陷。
**做法**：系统设置里扫码绑定 TOTP（Google Authenticator / 微软验证器 / 1Password 均可），
登录时二次校验；绑定失败不会把自己锁死（保留恢复码）。
**风险**：中 —— 处理不当会把自己关在门外，必须**先做恢复码**再启用。
**验收**：绑定后登录需验证码；用恢复码能登录；解绑流程可用。

### D2 · MCP 只读令牌

**为什么**：现在 MCP 只有一把"万能钥匙"，给出去就是全权。
**做法**：令牌分级 —— `full`（全权）/ `readonly`（只能调只读工具）；设置页可生成多把。
**风险**：低；重点是**工具白名单要维护好**，别让只读令牌调到写工具。
**验收**：用 readonly 令牌调 `create_website` 被拒，调 `list_websites` 成功。

## 四、P2 体验与视觉（E1 / E2）

> 原则：**每个特效都要有降级路径，手机端与低配设备不掉帧**。
> 明确不引 Three.js 全景 3D —— 光运行时 3.2MB gzip，这台 2 核机器和手机端都要掉帧，
> 那是"为了炫牺牲流畅"，与本方案 0.3 条冲突。

### E1 · 便利性（低风险，高感知）

| 项 | 说明 |
| --- | --- |
| **命令面板** | `Ctrl/Cmd + K` 唤起：跳页面、搜站点、执行动作（"续签证书""清缓存"） |
| 全局搜索 | 一个框搜站点 / 域名 / 容器 / 记录 |
| 键盘快捷键 | `g d` 去仪表盘、`g w` 网站、`/` 聚焦搜索；面板里有速查 |
| 表格偏好记忆 | 列显示/隐藏、每页条数、排序记到 localStorage |
| 密度切换 | 紧凑 / 舒适两档（信息密度对运维很关键） |
| 导出 CSV | 站点 / 证书 / 日志 / 容器列表一键导出 |
| 深浅色跟随系统 | 现在只能手动切，加"跟随系统"档 |
| 批量操作 | 从"选择多个站点 → 批量申请证书 / 批量清缓存"扩展 |

### E2 · 动效与视觉特效（务实路线）

**动效层（先把地基打好）**
- 令牌已加 `--ease-out`（进场）/ `--ease-in`（退场）/ `--dur-page`
- **页面切换**：View Transitions API（Chrome/Edge 原生，零依赖）+ 不支持时降级为淡入
- 列表首屏 stagger（40ms 间隔，只在首次进入时播）
- KPI 数字变化用 count-up（不重排布局）
- 侧栏展开/收起用 FLIP（先量后动，避免跳变）
- 骨架屏统一成一套扫光

**3D / 高级特效（全部零依赖、可降级）**
| 位置 | 效果 | 代价 | 降级 |
| --- | --- | --- | --- |
| 登录页 | 极简 Canvas 场线（缓慢流动，呼应"数据流"） | < 8KB，requestAnimationFrame | 手机/低端机 → 静态渐变 |
| 仪表盘 KPI 卡 | 指针跟随的 CSS 3D 微倾斜 | 纯 transform，GPU 合成 | `@media (hover: none)` 关闭 |
| 侧栏 / 登录 Logo | hover 时 3D 翻转 | CSS `preserve-3d` | 触屏不触发 |
| 数据加载 | 图表从中心"生长"而非直接出现 | ECharts 动画 | reduced-motion → 直接显示 |

**兼容性与流畅度硬指标（要拿数据说话）**
| 指标 | 目标 | 怎么量 |
| --- | --- | --- |
| 首屏 JS | ≤ 120KB gzip | `vite build` 产物统计（当前 element 分包 302KB，需进一步按需拆分） |
| 列表滚动 | 1000 行 60fps | 虚拟滚动 / `content-visibility` |
| 交互延迟 INP | < 100ms | Lighthouse |
| 长任务 | 巡检/部署不阻塞 UI | 已用异步 + 状态区块 |
| 目标浏览器 | Chrome/Edge 100+、Safari 15.4+、Firefox 100+、iOS 15.4+ | 特性检测 + `@supports` |
| 无障碍 | `prefers-reduced-motion` 全程尊重 | 已有全局兜底 |

### G4 · Git 工作流规范（P1）

## 六、明确不做（及理由）

| 不做 | 理由 |
| --- | --- |
| **定时备份 / 自动备份** | 你明确说不要；服务器 40G 已用 59%，备份会吃掉最后空间 |
| 多服务器纳管 | 需求还没出现，过早抽象会让所有接口都多一层"选服务器" |
| 接管 WAF / 防火墙 | 风险高（改错直接把公网访问切断），宝塔自带够用 |
| Three.js 全景 3D、大颗粒粒子 | 违背"流畅度"要求，2 核服务器与手机端都会掉帧 |
| Grafana / Sentry / ELK 自托管 | 内存与存储都撑不住，且与本系统职责重叠 |
| 引入付费组件库 | 你的红线：只用免费开源（MIT） |
